## 3. 优先复核的物理参数

### 3.1 轮组可能并不完整，且刚体分组需复核

CSV 的两个 wheel link 各只列 5 个部件，名称为 MOTOR_M3508、BaseMount、BaseTopCover、OutputInterLayer、OutputBase，未见明确命名的轮胎/胎面。这个证据提示 60 mm 可能只是当前电机/齿轮箱外形半径，不能直接拿它建立训练接触轮。部件名本身不足以证明胎面一定缺失，须回到 CAD 或实物核实。

还要确认 wheel link 内所有选中零件是否确实一起绕轮轴连续转动；若有固定于小腿的电机定子、箱体或支架，它们不能随 continuous joint 一起旋转。错分会改变旋转惯量、碰撞和运动外形。不要通过随意改轮半径或质量掩盖这个问题。

### 3.2 机身惯量需要重点确认

base_link 惯量主值为 0.04363468、0.06096903、0.07607293 kg·m²，数学上合法。由 sqrt(I/m) 得主轴回转半径约 45.36、53.61、59.89 mm；机身网格跨度为 436.5×622.0×446.5 mm。惯量表示质量相当集中，外形跨度本身不能证明错误，但应优先核对。

在 SolidWorks 用完全相同的 base_link 组件选择，核对评估→质量属性的质量、质心和关于质心的惯量；检查是否启用了覆盖质量属性、是否只修改质量而未同步惯量、单位及惯性参考坐标是否正确。不得直接用包围盒均匀长方体公式覆盖原值。

### 3.3 限位和驱动能力不能当实物参数

- 四个腿关节 -100..100 rad，相当于约 ±5729.6°，显然是占位活动范围，不是有效机械限位。
- 全部 effort=30 N·m，文件内没有本机电机/减速比/热限制/虚拟关节映射的验证依据。
- 全部 velocity=1000 rad/s，约 9549 rpm；若按 60 mm 滚动半径换算则为 60 m/s，明显不适合作为本阶段低速运动的已确认范围。
- 虚拟串联关节力矩与实际驱动电机力矩不必相等，需要机构映射后校核。

这些值可留作原始导出记录；正式动力学与训练配置必须明确机械可达域和驱动限制。现有文件没有 damping/friction 标定，也没有气弹簧动力学，第一阶段简化可以接受，但需写明近似边界。

## 4. 与训练代码的直接不兼容

### 4.1 长度改对仍不足够

当前 q=0 时，髋到轮轴的平面距离为 0.405396716 m；训练 legged_robot.py:170 起的公式带小腿 pi/2 偏置。如果只把 l1/l2 改为 0.21/0.25、保持当前关节零位，公式算得 0.326496554 m，低约 19.46%。因此必须一起转换零位和正方向，并通过随机姿态正运动学对拍。

当前原任务仍使用 infantry_V4_increase.urdf，l1=0.175、l2=0.208；不能直接沿用其默认角、初始化高度或 PD 来认定新车兼容。

### 4.2 关节顺序存在冲突

| 来源 | 静态顺序/描述 |
|---|---|
| 本版 URDF XML | 左大腿、左小腿、左轮、右大腿、右小腿、右轮 |
| 本版 controller_joint_names YAML | 右大腿、右小腿、右轮、左大腿、左小腿、左轮 |
| 参考 infantry_V4_increase.urdf XML | 右侧在前 |
| 实施说明 4.3 | 写左侧在前 |
| 实施说明 5.7 | 写 YAML 右侧在前 |

XML/YAML 排列都不是 Isaac Gym 实际加载顺序的证据；源码通过 get_asset_dof_names 获取 DOF 名称，却在腿长公式、动作和观测中使用固定索引。需要实际打印顺序并建立显式名称映射，才能判断策略语义。当前不应武断宣称复旦所有策略统一左先或右先。

### 4.3 左小腿轴不能按左侧统一处理

在 SW 基座坐标、q=0 时：

| 关节 | 轴向 |
|---|---|
| lf0_Joint | +X |
| lf1_Joint | -X |
| l_wheel_Joint | +X |
| rf0_Joint | -X |
| rf1_Joint | -X |
| r_wheel_Joint | -X |

原修复报告及 JOINT_FIX_NOTES 表格与本次计算一致；实施说明 5.7 和局部说明正文把左侧概括为 +X，漏掉了左小腿翻转。应纠正文档，并逐关节定义符号，不能为整侧统一乘一个符号。局部轴 0 0 1 本身不因此被判错。

### 4.4 接触模型和任务尚未准备好

- 7 个网格共 1,178,386 个三角形；base_link 单独 1,020,702 个、51,035,184 字节。visual 与 collision 完全复用，需另建训练用简化碰撞体；本次未测试加载器如何处理碰撞网格。
- 原任务继承 foot_name="None"，本模型没有匹配名称，会得到空的 feet_names；需显式选择 left_wheel/right_wheel，并在加载后检查接触体索引。已有接触奖励是否启用需按最终任务配置决定。
- 当前 envs 只有 base 和 wheel_legged，注册仍只有 wheel_legged；本版专用任务和教师迁移入口未交付。
- 25 维当前观测、5×25 历史、6 维动作的结构可以兼容，但顺序、零位、缩放、历史采样和力矩映射还没有完成对齐。

## 5. 下一步及验收条件

1. **立即可做 G0/G1 文件工作**：保留原包，建立独立训练资产和参数表；整理真实轮组、CAD 质量属性、机械限位、电机能力的待确认项；检查指定训练环境。
2. **完成 G1**：确认轮胎和 wheel 刚体归属；转换坐标/零位/符号，同时处理惯性和网格变换；保留真实 visual，建立简化 collision；建立专用任务、显式关节与接触体映射；随机姿态验证训练公式等于 URDF 正运动学。
3. **进入 G2 物理验证**：单机器人、关闭随机化，检查加载顺序、重力、尺度、初始穿透、轮地接触、逐关节小动作、观测和受限力矩；确认 25/125/6 与 PD 语义。动力学参数未确认时只能作为临时模型实验，不能宣称本机验证通过。
4. **通过 G2 后才进入 G3**：按既定教师权重恢复→教师辅助 PPO→独立 PPO 路线；本次没有启动训练或修改部署固件。

最少仍需确认：完整轮胎实际直径及 wheel link 的选件范围、base_link 的 SW 质量属性、四个腿关节可达范围和驱动能力、训练环境所在位置与访问方式。实机编码器标定和烧录不属于本次检查。
