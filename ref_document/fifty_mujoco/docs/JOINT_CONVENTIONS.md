# 关节约定、参考姿态与闭环映射（S3）

> 2026-10-30 建立。对应 `progress.md` §23.4（任务 B）与 §24.11。
> 本文回答三个"以前只能靠口头约定"的问题：**每个关节的正方向是什么、左右怎么镜像、
> 站立参考姿态是哪一个**——并且每一条都能被测试或命令复算。

## 1. 为什么需要这一层

`progress.md` §23.4 允许仿真自行约定正方向与零位，但要求**同一条转换必须作用到**
位置、速度、控制目标、Jacobian、力矩映射和观测。写在文字里无法校验，所以约定写进
`configs/joint_conventions.yaml`，并用两条独立来源核对：

| 来源 | 校验内容 |
|---|---|
| `assets/mjcf/fifty_train.xml` | 每个关节在**基座坐标系**中的实际轴向（由 body 四元数逐级复合得到，纯标准库，不跑物理） |
| `configs/policy_contract.yaml` | 左右符号 `signs` |
| `configs/robot.yaml` | 零位（`default_angles_rad`）与限位（`limits_rad`） |

任何一项被改动而另一处没跟上，`tests/test_joint_conventions.py` 失败；
`fifty-mujoco joint-conventions` 会把三张表并排打印。

## 2. 六路通道（模型/策略顺序）

表中零位来自旧串联模型；最后一列描述目标闭链驱动职责，两者不能直接数值等同。转换见 §3–§4。

| 通道 | 侧 | 基座轴向 | sign | 零位 (rad) | 驱动的真实坐标 |
|---|---|---|---:|---:|---|
| `rf0_Joint` | 右 | +Y | +1 | +2.055422 | 大腿角（HIP→KNEE） |
| `rf1_Joint` | 右 | +Y | +1 | −2.559268 | 曲柄角（绕髋轴，**地面参考**） |
| `r_wheel_Joint` | 右 | +Y | +1 | 0 | 轮 |
| `lf0_Joint` | 左 | −Y | −1 | −2.055422 | 大腿角 |
| `lf1_Joint` | 左 | −Y | −1 | +2.559268 | 曲柄角（地面参考） |
| `l_wheel_Joint` | 左 | **+Y** | **+1** | 0 | 轮 |

**曲柄参考系（2026-10-31 确认）**：两台 DM-8009 都固定在 `【复用交C件】髋关节大铝件`
（车体架，**不**随腿转动），操作者确认"转大腿时大腿和小腿一起转；只转小腿时只有一台电机转"。
因此曲柄角在**地面系**测量：`crank = 电机角`，不带大腿项。`mechanism/transmission.py`
本来就是这么建模的，无需改动。

**这张表是核对出来的，不是抄来的。** 校验过程中立刻发现一处原本写错的约定：
左轮的有效轴是 **+Y**，与右轮相同，而不是腿关节那样的镜像 −Y。
原因是"向前滚动的轮子两侧旋转方向相同"。这正是策略契约里符号是
`(+1, +1, +1, −1, −1, +1)` 而不是整体取反的原因。

**语义**：`q_left = sign · q_right`（对称姿态下）。速度与力矩继承同一个符号；
零位是**位置**偏置，绝不能加到速度或力矩上。

**明确不是**：`zero_rad` 是**资产约定**，不是实车编码器零位；`sign` 也不证明真实电机的接线方向。
这两项留在上车前标定（§23.4 末段）。

## 3. 参考站立姿态（任务 B 第 4 项）

`configs/joint_conventions.yaml: reference_pose`，推导链每一步都有来源：

| 步骤 | 值 | 来源 |
|---|---|---|
| 目标基座高度 | 0.4647513721610853 m | 环境标称高度（`stand_eval` 报告与奖励里的 `nominal_height` 一致） |
| 轮半径 | 0.06 m | `robot.yaml: geometry.wheel_radius_m`（provisional） |
| 髋→轮弦长 | 0.4047513721610853 m | 上式相减，轮在髋正下方 |
| (thigh, shin) | −2.115162642285236 / −1.120740359909000 rad | 两连杆解析 IK |
| crank | −1.026430011344950 rad | `mechanism/bridge.py` 在已确认闭链上求解 |
| det J | +0.039573581820094 | 非奇异 |

**两条 IK 支路只有一条成立。** 另一条（thigh ≈ −58.81°）在目标弦长下，闭链只能通过一个
**奇异**根（曲柄与大腿共线、推杆够不到）到达，`bridge` 会拒绝它。所以参考姿态是唯一的，
不是"挑了一个"。

**结果自检**：`fifty-mujoco joint-conventions` 会用目标弦长**重新解一遍**，
与存储值的差 ≤ 1e-9 rad，否则判 `failed`。

**2026-10-31 离线纠正**：URDF 仍决定坐标与安装偏移，但平面杆长按垂直关节轴的投影计算，结果为 **210 / 250 mm**。210.315 / 253.947 mm 是包含侧向错位的三维原点距离，不能当平面杆长。撤回“参考姿态必须移动 23.1 mrad”的结论，末端连杆保持 **96.600 mm**。

弹簧销距包含 **11 mm** 侧向错位：三维距离平方 = 平面距离平方 + 11²（mm²）。装配姿态 194.949622 mm，正下方参考姿态 227.760939 mm；相对约 250 mm 自由长度，**已压缩 22.239061 mm，剩余可压缩 52.760939 mm**。理想平面机构折角 0–π 的三维销距包络为 152.152021–249.126126 mm，最小值不是恰好在 π 处。75 mm 行程对应允许销距 175–250 mm；在轮位于髋正下方的假设下，允许高度约 0.281189651–0.520 m。这是几何窗口，尚未加入全部闭链支路、机械限位、碰撞与动力学约束，不能把气弹簧当作已经验证的机械硬限位。

**旧串联默认姿态与新闭链参考姿态不同**：旧默认轮心在髋前方 22.865346 mm，向下 404.751372 mm，不是正下方。上表两个角是绝对杆件角；右侧串联转换为 q_hip = −thigh、q_knee = thigh − shin −π/2，得到 +2.115162642 / −2.565218609 rad，左侧相反。曲柄 −1.026430011 rad 是机构平面绝对角，不能直接当 MJCF 关节 qpos；还需按模型零位换算并初始化全部被动关节。

这些转换写入配置供后续集成使用，本轮 **没有更改 robot.yaml 默认角或 policy_contract.yaml**。必须在完整闭链模型、控制语义与重置实现就绪后一起切换。真实弹簧参数记录为 450 N / 约 250 mm / 75 mm，当前运行 gas_springs 仍为旧锚点 300 N。首轮可采用明确标注的 450 N 常力近似，完整力曲线是后续改进项。

## 4. 串联等效模型 ↔ 真实闭链（`mechanism/bridge.py`）

MJCF 是**等效串联**两连杆（髋关节 + 膝关节）；真机是**两自由度五杆**，
第二台电机绕髋轴驱动曲柄，膝角是被闭链决定的结果，不是自由坐标。

```
shin_angle(tx, thigh, crank)        (thigh, crank) -> 小腿方向
crank_roots(tx, thigh, shin)        (thigh, shin)  -> 所有能闭合的曲柄角
mechanism_from_serial(...)          选一个可控的根
wheel_jacobian(tx, thigh, crank)    d(轮心)/d(thigh, crank)，数值中心差分
```

**为什么不能写成一张 sign/bias 表**：`rf1`（等效"膝"）与真实曲柄角之间是**非线性**关系，
只有大腿角是两侧共享的（都是 HIP–KNEE，G01 = 210 mm）。凡是把两者当仿射关系的写法，
在参考姿态附近可能看起来对，一到大幅度就不成立。

**过滤掉的两种假根**（两者都会给出一个"看起来能解"的错误答案）：

1. **±π 绕回**：残差是角度差，穿过 ±π 时符号翻转，但并没有过零；
2. **可行域边界**：推杆够不到的地方小腿方向会跳变，二分法会收敛到边界而不是解。

判定规则：保留的根必须残差 ~0 **且**左右两侧都仍然闭合，否则标记为不可用。
奇异的根（|det J| < 1e-6）同样不参与选择，但会在错误信息里列出来。

## 5. 命令与复现

```bash
cd ref_document/fifty_mujoco
uv run python -m fifty_mujoco.cli joint-conventions      # 打印并核对三张表 + 复算参考姿态
uv run python -m fifty_mujoco.cli mechanism-check        # 闭链闭合与可行性
uv run pytest tests/test_joint_conventions.py -q          # 本轮修改后尚未运行
```

`joint-conventions` 报告写在 `reports/joint_conventions_<UTC>.json`。
