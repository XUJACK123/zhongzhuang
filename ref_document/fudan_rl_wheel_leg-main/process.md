## 1. 文档交付与总体目标

本次只更新 `process.md`，不同时修改训练代码、生成新机器人模型或启动训练。后续按本方案分阶段实现，并更新文末进度表。

已确认的选择：

- 第一阶段只实现**站立、低速前后移动、低速转向**，暂不训练跳跃、台阶和自救。
- 新机器人的 URDF、质量与惯量参数尚未准备完整。
- 采用**恢复 ONNX 权重 → 教师辅助 PPO → 独立 PPO**，不从随机网络开始重新模仿。
- 允许每次训练约 3 小时，保存完整 checkpoint，之后继续。
- 基于 `plane` 分支开发，保留原 `wheel_legged` 任务；新增任务 `wheel_legged_custom`，避免修改原任务后无法对照。
- 所有适应训练先在仿真完成；H723 固件、模型部署和实机试验另行验收。

最终训练数据流：

```text
你的机器人 URDF + 动力学参数 + 任务配置
                   ↓
         Isaac Gym 目标机器人环境
                   ↓ 观测、历史、奖励
       学生 actor + encoder + critic
                   ↑
   冻结教师提供动作约束，影响逐步降低
                   ↓
       学生独立 PPO 训练与独立评估
                   ↓
         完整 .pt + 部署 .onnx
                   ↓
       使用同一目标机器人做 MuJoCo 验证
```

这里的“继续训练”表示继承原策略的 actor/encoder 权重后适应新动力学，不是恢复原作者完整的 PPO 现场。只有推理 ONNX，无法找回原 critic、优化器动量和训练迭代数。

## 2. 当前工程事实与教师选择

### 2.1 已核对的模型接口

两个现有 ONNX 均包含：

| 项目 | 实际内容 |
|---|---|
| 当前观测输入 | `obs`，形状 `[batch, 25]` |
| 历史观测输入 | `obs_history`，形状 `[batch, 125]` |
| 动作输出 | `actions`，形状 `[batch, 6]` |
| 权重 | 有命名清晰的 `encoder.*`、`actor.*` |
| 完整训练状态 | 没有 critic、探索参数、优化器和训练进度 |

因此优先恢复 actor、encoder 的权重，重新创建 critic 和优化器。恢复后必须验证输出一致，不能仅凭权重名字判断转换成功。当前完成的是 ONNX 文件的静态结构检查，尚未执行 ONNX/PyTorch 数值等价测试。

第一阶段选用：

```text
mujoco/actor/yuntai/上台阶3_angz+.onnx
```

该模型在现有 MuJoCo 脚本中被用于 `plane` 模式，作为第一阶段候选教师。另一个模型 `p60.50.2把urdf中力矩限制为50.onnx` 用于跳跃，不纳入本阶段。

教师对应的历史配置位于：

```text
plane/logs/wheel_legged/上台阶3_angz+/
```

该目录是配置线索，不是完整 checkpoint，也不能单靠目录名证明模型训练来源。需要通过教师复现评估确认配置可用。

### 2.2 不能直接沿用当前默认配置

候选教师的历史配置与当前 `plane` 默认配置存在差异，例如默认关节角、PD 和速度观测缩放。

教师配置清单必须记录：

- 六关节顺序与方向。
- 默认关节角。
- 观测排列、缩放、截断。
- 历史顺序、初始化方式、更新周期。
- 动作含义及缩放。
- PD、力矩限制。
- 教师 ONNX 的 SHA-256。
- 配置来源和复现结果。

优先使用对应历史配置与现有 MuJoCo `plane` 预设交叉核对，禁止混搭当前默认配置。

### 2.3 策略输出不是六维电机力矩

当前策略顺序为：

```text
左侧关节 0、左侧关节 1、左轮、
右侧关节 0、右侧关节 1、右轮
```

四个关节动作转为位置目标，两个轮动作转为速度目标，再经 PD 得到力矩。

现有 H723 底座的通道顺序则为：

```text
LF、LR、RF、RR、LW、RW
```

后续需要明确的顺序、方向及机械坐标转换。若机构存在串并联坐标转换，还需相应运动学和力矩映射。不能把 ONNX 的六个输出直接传给 `chassis_submit_torque()`。

### 3.3 模型验收顺序

1. 从 CAD 导出各刚体质量、重心和惯量，核对材料密度、网格单位和惯量参考系。
2. 检查惯性张量对称性、正定性及物理合理性。
3. 检查碰撞几何、关节轴、限位和初始穿插。
4. 在仿真中加载一个机器人，打印实际 DOF 名称及顺序。
5. 通过名字建立策略到仿真 DOF 的映射，不依赖 URDF 文件中的排列顺序。
6. 在仿真中逐关节施加小目标，核对方向和关节对应关系。
7. 核对站立姿态和轮地接触，再允许训练。

若真实机构是闭链或并联机构，必须明确训练使用的等效六自由度模型及其与物理电机的映射。不能只删掉闭链约束，让模型“能加载”就开始训练。

同时修正配置存档逻辑：保存运行时解析后的完整配置，不能只依赖原来的源码复制列表。

### 4.2 ONNX 权重恢复

新增 `prepare_transfer.py`，完成：

1. 检查 ONNX 输入输出、图结构、数据类型和全部 actor/encoder 权重。
2. 根据实际权重形状重建 PyTorch 网络，不只依赖硬编码默认值。
3. 严格匹配全部参数；缺失、多余、转置或形状不符时明确失败。
4. 使用批大小 1、32、256 的有限输入，以及仿真采样观测，对比 ONNX 与 PyTorch。
5. 测试容差采用 `atol=1e-5、rtol=1e-4`，并记录最大误差。
6. 通过后生成初始化 `.pt`、冻结教师副本和转换报告。

学生与教师的 actor、encoder 初始权重相同；critic 随机初始化。

教师在训练期间不更新。完成等价验证后，训练时使用冻结 PyTorch 教师进行批量推理，避免每一步在 GPU 仿真与 CPU ONNX Runtime 之间复制数据。ONNX 保留为转换校验基准。

恢复失败时停止该步骤并报告原因，不自动切换到未经验证的模型或重新从零训练。

### 4.3 观测和动作适配

保留教师的 25 维接口：


历史为 5 帧，按现有实现从旧到新排列。

控制周期初始保持策略 10 ms、物理步长 5 ms，与候选教师配置一致。后续改变周期需要作为独立实验。

### 4.4 教师损失与编码器训练

辅助损失采用学生动作均值和教师动作：

\[
L_T=\frac{1}{6}\sum_{i=1}^{6}
\left(\frac{\mu_{S,i}-a_{T,i}}{\sigma_i}\right)^2
\]

其中 `mu_S` 是学生动作均值，`a_T` 是同一观测及历史下的教师动作；`sigma_i` 来自教师复现数据的动作标准差，下限为 0.1。转换准备阶段保存该统计量，训练中不动态改变。此处用于损失归一化的 `sigma_i` 不等同于学生用于探索的策略标准差。

总损失：

\[
L=L_{\mathrm{PPO}}+\lambda L_T
\]

初始工程默认值为 `lambda_0=0.1`，记录 PPO、教师损失及 actor 梯度量级，用实验判断该值是否合理，不把它作为通用最优值。

本方案保留原编码器语义：

- 恢复 encoder 权重，不从随机编码器开始。
- PPO 和教师动作损失更新 actor，保持现有 latent detach 路径。
- encoder 由原有仿真真值辅助损失更新，保留其独立优化器。
- 不额外引入第二个更新同一组 encoder 参数的蒸馏优化器。
- 测试确认各阶段只有预期参数被更新。

进入 PPO 后，执行动作必须来自学生策略。教师只提供辅助标签，不能把教师动作或教师与学生混合动作当成普通学生采样送入现有 PPO。

## 5. 训练阶段与教师退出规则

### 5.1 阶段 A：教师和模型复现

先完成两项独立评估：

- 教师在原机器人及匹配配置上的表现。
- 教师在目标机器人上的表现。

原模型复现失败时，先检查预处理、默认角度、PD、模型和动作映射，不开始长时间迁移训练。

目标模型表现差不代表转换失败，也不要求目标教师达到学生最终门槛。它用于判断迁移难度和教师约束是否可能有害。

### 5.2 阶段 B：critic 预热

恢复策略后，先运行 20 个 rollout/update 周期：

- 固定 actor、encoder 和探索标准差。
- 学生在目标环境采样。
- 只训练 critic。
- 探索标准差初始设为 0.05，单位为策略动作单位。

此阶段不使用旧教师的价值估计，也不假装恢复了原训练进度。

### 5.3 阶段 C：教师辅助 PPO

开启 actor、critic 和 encoder 的正常训练。

第一版使用：

- 主优化器学习率 `1e-4`，encoder 学习率 `1e-4`。
- 保留 PPO 的 KL 监控；主学习率允许自适应，但上限为 `3e-4`。
- 初始可学习的探索标准差为 0.05，限制在 0.01～0.3。
- 教师权重依次为：

```text
0.1 → 0.05 → 0.025 → 0.01 → 0
```

这些是第一轮实验默认值，后续修改必须记录为新的实验配置。

### 5.4 独立评估协议

每 50 次 PPO 更新执行一次独立评估：

- 学生独立控制，使用动作均值，不允许教师接管。
- 共 200 个 episode，每个 20 秒。
- 站立、前进、后退、左转、右转各 40 个。
- 前后速度为 ±0.3 m/s，转向角速度为 ±0.3 rad/s。
- 高度使用已核对的目标站立高度 `h0`，不写死为原机器人的高度。
- 每类包含目标标称参数与预先生成的轻度扰动场景。
- 质量/惯量缩放 ±5%、重心偏移 ±5 mm 作为第一版评估扰动；参数集固定并保存。
- 验证种子独立于训练；最终验收再使用一套未用于调权的保留种子。

失败判据单独定义，不能只读取现有 episode 的 done：

- roll 或 pitch 绝对值超过 30°并持续 0.2 s。
- 基座高度低于 `0.6 × h0` 并持续 0.2 s。
- 发生禁止的机身接触、关节越限或非有限数值。
- 环境发生其他真实失败终止。

正常时间结束不算失败；用于该评估的平面场景不设置可触发正常行驶越界的有限地形边界。

### 5.5 降低教师权重的门槛

每次评估需要同时满足：

| 指标 | 第一版门槛 |
|---|---|
| 20 秒无失败完成率 | 总体 ≥95%，每类 ≥90% |
| 前向速度 RMSE | 每类 ≤0.10 m/s |
| 转向速度 RMSE | 每类 ≤0.15 rad/s |
| 姿态偏差 | 每类 roll/pitch 绝对值的 P95 ≤15° |
| 力矩饱和 | 每个电机饱和时间比例 ≤5% |
| 数据有效性 | 无 NaN/Inf |

跟踪误差忽略开始后的前 2 秒，失败计数仍覆盖完整 episode。

**连续 3 次评估通过，才降低一级教师权重。** 动作模仿误差只记录，不作为后期必须下降的条件；学生适应新机器人时允许偏离教师。

这些门槛用于本阶段仿真实验，不代表实车安全认证，也不要求学生超过旧教师的回报才能退出教师。

### 5.6 回退与停止条件

每次降权前保存已通过验证的 checkpoint 及评估基线。

降权后，出现以下退化并连续两次评估成立，回退：

- 完成率下降超过 5 个百分点。
- 速度或转向 RMSE 比降权前增加超过 `max(基线的10%, 0.02 对应单位)`。

新出现非有限值或明显越限时，立即终止当前试验并保留诊断，不等待第二次评估。

回退恢复模型、两个优化器、学习率、教师权重和阶段状态；新仿真 episode 重新开始。

同一级降权最多重试两次，再失败则保存并停止自动推进。连续 1000 次更新仍无法通过当前门槛，也停止并输出诊断，不无限训练。

若教师约束疑似妨碍适应，下一轮开展相同起点、相同预算的低权重/零权重对照实验，通过目标任务表现选择；不根据单次训练回报自动认定教师有害。

### 5.7 独立训练的正式起点

教师权重首次达到零，进入“独立 PPO 试运行”。

至少完成 150 次更新，并在此期间连续 3 次独立评估通过，才将状态标为：

```text
INDEPENDENT_PPO
```

零权重试运行时教师损失不产生梯度；保留教师资产与此前 checkpoint 供回退。正式进入独立阶段后，取消训练过程中的教师推理和教师损失，继续保留阶段 C 的保护指标、checkpoint 和独立评估。

教师权重、通过次数、失败次数和试运行进度全部存入 checkpoint；分段训练不得重置这些计数。

**不以“训练满 N 个回合”或“训练满三小时”作为教师退出条件。** 三小时只决定本次进程何时保存退出，学生能力和评估门槛决定当前训练阶段。

## 6. 三小时分段训练与 checkpoint

新增参数：

```text
--max_wall_time_s 10800
```

表示本次进程的总运行预算，包含训练和评估。到达预算后不再启动新一轮工作，在当前完整更新结束后保存退出，允许少量越过三小时边界。

保存策略：

- 每 100 次更新保存一次编号 checkpoint。
- 每 10 分钟额外保存一次。
- 阶段变化、通过门槛、回退和正常退出时保存。
- Ctrl+C / SIGTERM 仅设置停止标志，在更新边界完成保存。
- 写入临时文件后原子替换，保留上一份有效 checkpoint。
- 强制杀进程或断电只能恢复到最近完成的 checkpoint。

checkpoint 至少包含：

- actor、encoder、critic、探索标准差。
- 主优化器和 encoder 优化器。
- 自适应学习率等算法状态。
- 正确累计的更新数、采样步数、训练耗时。
- 教师阶段、权重、门槛连续计数、回退次数。
- Python、NumPy、PyTorch CPU/CUDA 随机数状态。
- 配置、模型文件与教师文件的哈希。
- 已启用的课程状态及评估定义。

修复现有 runner 的周期保存迭代数陈旧、最终编号未累计、漏存 encoder 优化器问题。

普通 resume 必须校验配置和资产兼容性。改变 URDF 或动力学配置属于新迁移实验，不能静默当作原训练的完整续跑。

恢复时重建仿真、重置 episode 和历史缓冲，不承诺与不中断运行逐位一致。必须区分“学习状态延续”和“完整仿真现场恢复”。

## 7. 环境准备与训练命令

### 7.1 训练环境

以 Linux NVIDIA GPU 环境为实施目标，先验证 Isaac Gym Preview 4 示例，再锁定依赖。该旧版 Isaac Gym 的官方平台与 Python 支持见 [NVIDIA 下载说明](https://developer.nvidia.com/isaac-gym/download)。

只在该环境安装 `plane`：

```bash
conda activate leg
cd ~/fudan_rl_wheel_leg-main/plane
pip install -e .
```

以上命令以训练机上已建立 `leg` 环境、已安装 Isaac Gym 和已放置工程为前提；不表示本次已完成环境安装。

`plane` 和 `jump` 使用同名 Python 包，不在同一环境交替安装，以免训练入口引用错版本。

实施时交付经过验证的依赖锁定文件。修复源码中与选定 Python 版本不兼容的语法；未确定 GPU、驱动和 CUDA 前，不声称某套依赖已验证可用。

初始并行环境数设为 256，先跑通再扩大；不直接沿用 8192。

### 7.2 计划新增的命令

**以下接口需要实施后才可运行，当前工程尚不具备。** 所有相对路径均以训练机上的 `fudan_rl_wheel_leg-main/plane` 为工作目录。Linux 路径需按实际工程位置调整，不能直接使用 Windows 的 `D:\` 路径。

**第一步：检查机器人模型**

```bash
python wheel_legged_gym/scripts/validate_robot.py \
  --task wheel_legged_custom \
  --num_envs 1
```

输出关节映射、质量/惯量摘要、资产缺失项和模型报告。

**第二步：恢复并验证教师权重**

```bash
python wheel_legged_gym/scripts/prepare_transfer.py \
  --teacher ../mujoco/actor/yuntai/上台阶3_angz+.onnx \
  --teacher_profile plane_stairs \
  --out artifacts/transfer_init
```

**第三步：分别评估原机器人与目标机器人**

```bash
python wheel_legged_gym/scripts/evaluate_transfer.py \
  --policy artifacts/transfer_init/student_init.pt \
  --suite source_baseline \
  --headless

python wheel_legged_gym/scripts/evaluate_transfer.py \
  --policy artifacts/transfer_init/student_init.pt \
  --suite target_low_speed \
  --headless
```

**第四步：启动第一段训练**

```bash
python wheel_legged_gym/scripts/train_transfer.py \
  --task wheel_legged_custom \
  --init artifacts/transfer_init/student_init.pt \
  --num_envs 256 \
  --run_name custom_low_speed \
  --max_wall_time_s 10800 \
  --headless
```

**第五步：继续下一段三小时**

```bash
python wheel_legged_gym/scripts/train_transfer.py \
  --resume_checkpoint logs/wheel_legged_custom/实际运行目录/latest.pt \
  --max_wall_time_s 10800 \
  --headless
```

`--init` 表示新实验的初始化，`--resume_checkpoint` 表示完整续训，二者互斥。resume 默认读取 checkpoint 内配置，不重新套用当前文件中的默认参数。上面“实际运行目录”是需要替换的占位内容。

**第六步：查看日志**

```bash
tensorboard --logdir logs/wheel_legged_custom
```

日志至少显示回报、五类完成率、跟踪误差、姿态、饱和比例、探索标准差、教师损失、教师权重和当前阶段。

**第七步：评估并导出**

```bash
python wheel_legged_gym/scripts/evaluate_transfer.py \
  --policy logs/wheel_legged_custom/实际运行目录/best_validated.pt \
  --suite target_holdout \
  --headless

python wheel_legged_gym/scripts/export_transfer.py \
  --checkpoint logs/wheel_legged_custom/实际运行目录/best_validated.pt \
  --out exported/custom_wheel_leg
```

导出器读取 checkpoint 中的网络配置，不能继续使用固定历史长度的硬编码脚本。

## 8. 测试、交付和实施顺序

### 8.1 软件测试

- ONNX/PyTorch 多批量输出等价，缺权重和错误维度明确失败。
- 25 维观测排列、5 帧历史更新和 episode 重置正确。
- 六通道映射、动作到位置/速度目标及力矩换算正确。
- critic 预热时 actor/encoder 不变化。
- 教师始终冻结，教师标签不混入 PPO 行为采样。
- 门槛连续通过、降权、零教师试运行、失败回退和重试上限正确。
- checkpoint 恢复两个优化器、累计编号和教师阶段。
- 人为中断保存不会破坏上一份有效 checkpoint。
- 时间预算通过短时间模拟测试验证，不用等待三小时。
- 原 `wheel_legged` 任务关闭迁移功能时仍可运行。

### 8.2 GPU 仿真验收

按顺序执行：

1. 一个目标机器人加载与关节检查。
2. 教师原环境复现和目标环境基线。
3. 32 个环境的短训练，验证梯度、奖励和保存。
4. 中断恢复一次，核对训练状态连续。
5. 256 个环境运行一个三小时分段。
6. 完成教师退出流程后执行保留评估集。
7. 使用目标机器人模型做 MuJoCo 验证，而不是继续使用原机器人 XML。

### 8.3 最终产物

每次可交付实验包含：

- 可继续训练的完整 `.pt`。
- 部署用 `.onnx`。
- 观测、动作、历史、周期及关节映射元数据。
- URDF、网格、动力学参数与哈希。
- 环境依赖版本。
- 教师转换报告、训练日志及独立评估报告。
