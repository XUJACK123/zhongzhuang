# chassis_ref_new 当前进度与后续工作

更新日期：2026-10-25。本文只维护当前状态，不追加多份历史记录。当前已完成本轮源码修改、最终构建与主机测试；接下来进入单电机硬件验证。唯一使用说明及文件职责表见 [README.md](README.md)。

## 1. 整体目标

把原来的轮腿底盘控制工程整理为 **达妙 DM-MC02 / STM32H723 的六电机力矩执行底座**，再为这个底座提供一个可独立选择电机的小角度台架测试控制器。

当前阶段要解决：连接目标电机，指定 CAN 总线、命令 ID 和反馈 ID，使用遥控器允许输出，让目标电机缓慢转过一个小角度，并能观察反馈和停止原因。其他电机是否连接，不应阻止这个测试。

长期目标是在完成接线、方向、量纲、零点标定之后，接入强化学习控制器。底座只接受六维物理电机力矩，不内置 LQR，不把测试 PD 当成最终 RL 控制算法。

本轮只修改 `chassis_ref_new`。其他参考工程只读取，不修改。本轮不刷写、不使能真实电机、不进行整车运行。

## 2. 两种固件的区别

| 项目 | 正式底座：`TEST_MOTOR=0` | 台架测试：`TEST_MOTOR=1` |
|---|---|---|
| 控制目标 | 接收后续控制器的六维力矩 | 控制指定的一只电机 |
| 主动生成运动命令 | 不生成；无命令时零输出 | 测试控制器生成小角度轨迹和 PD 力矩 |
| 电机在线要求 | 六个电机在线，四关节使能 | 只要求目标电机在线，目标为关节时只要求该关节使能 |
| 电机发送范围 | 六个通道 | 目标通道；3508 同一个组帧的其他槽为零 |
| 保留保护 | 遥控、反馈、IMU、命令、CAN 故障及重新拨档 | 同样保留；电机集合缩小到目标，不关闭整条保护链 |
| 输出目录 | `build/default/` | `build/bench/` |
| 启动指示 | 绿色常亮、三声启动音 | 相同，独立于测试任务 |

**只有目标电机被选中，才会收到本固件的使能和控制指令。未选中的达妙电机不发送控制帧；这不等于能替其他控制器关闭那些电机。**

## 3. bench_motor_test 到底负责什么

`tests/bench_motor_test.c` 是会运行在 STM32 上的临时控制器，不是 PC 单元测试，也不负责直接发送 CAN。

```text
电机 CAN 反馈 + IMU + DR16
             ↓
chassis_task：汇总快照、执行安全状态机
             ↓ chassis_get_feedback()
bench_motor_test：判断双上档、目标在线、底座已允许输出
             ↓
bench_controller：生成小角度轨迹 → PD → 力矩限幅和变化率限制
             ↓ chassis_submit_torque(六维数组)
chassis_task：最终保护和输出权限判断
             ↓
chassis_protocol：根据统一配置编码 MIT 力矩帧 / 3508 电流帧
             ↓
CAN_receive：向目标总线发送
```

台架任务默认不编入正式固件。之前“看起来没有起作用”的主要可能原因已有源码依据：没有打开测试开关；切换编译开关复用了旧目标文件；只接一个电机却被全部六电机的在线条件锁住；或者实际 Master ID 与接收表不符。以上是代码层面的原因，尚未通过实机确认用户遇到的是哪一个。

## 4. 已完成的代码修改

### 4.1 小角度、慢速轨迹

新增 `tests/bench_controller.c/.h`，把控制算法从 FreeRTOS 任务中分离，方便在 PC 上直接测试。

| 参数 | 当前值 |
|---|---|
| 相对目标角度 | 默认 +5°，可设置负数反向；运行时拒绝绝对值超过 15° |
| 参考速度上限 | 5°/s |
| 参考加速度上限 | 10°/s² |
| 默认轨迹时长 | 约 1.5 s；实际到位时间受负载与控制参数影响 |
| 关节 PD | Kp=5，Kd=0.2 |
| 轮电机 PD | Kp=0.5，Kd=0.02 |
| 台架关节力矩上限 | ±1 N·m |
| 台架轮电机力矩上限 | ±0.2 N·m |
| 关节/轮力矩变化率 | 2 / 0.5 N·m/s |
| 实测速度停止阈值 | 0.5 rad/s，超限锁存停止 |
| 相对位移停止阈值 | 超过目标角度绝对值加 5° |
| 控制周期 | 2 ms；运行间隔超过 10 ms 锁存停止 |
| 未到位停止 | 5 s 内未达到误差小于 1°且速度小于 0.05 rad/s、持续 300 ms |

轨迹由真实经过时间计算，包含加速、匀速、减速；小行程自动成为三角速度曲线。电机实际速度仍取决于控制效果，所以另设实测超速保护，不能把“参考限速”当作实际速度一定满足的证明。

关节采用连续相对位移累计，跨编码零点时按配置范围解回绕，不对目标误差随意选择另一条整圈路径。位置、速度出现 NaN/Inf 或不合理跳变时清零并锁存测试故障。

启动等待完成以后才记录 `wake_time`；任务超期不连续补跑旧周期。停止直接清零，不经过力矩缓降。取消允许条件后重新运行会重新记录起点；测试内部故障则要求 S1 下档清除。

### 4.2 只检查、使能和驱动目标电机

新增 `application/chassis_motor_config.c/.h`，提供统一配置表和活动电机掩码。

- 正式版掩码为六路全开。
- 台架版只有一个位有效。
- `chassis_task` 的电机在线检查使用同一个掩码。
- 达妙清错和使能只作用于活动关节。
- CAN 仅启动当前需要的总线，不向未使用总线发送周期命令。
- 反馈路由与力矩编码使用同一份表。
- 3508 的原始反馈存储按电机索引寻址，不再错误地把“CAN1/CAN2”当作左右轮索引。

最新补充了 `chassis_feedback_health()`，将“目标是否在线、数据是否有限、反馈年龄和关节状态”汇总为可主机测试的函数，并已接入真实输出任务。取当前时间移到复制传感器快照之后，避免中断更新了时间戳、旧的 now 导致无符号年龄下溢。

### 4.3 分开命令 ID 和反馈 ID

当前默认接线仍保留原来的六路布局：

| 选择名 | 索引 | 总线 | 命令 ID | 反馈 ID |
|---|---:|---:|---|---|
| LF 左前关节 | 0 | 1 | 0x003 | 0x003 |
| LR 左后关节 | 1 | 1 | 0x004 | 0x004 |
| RF 右前关节 | 2 | 2 | 0x002 | 0x002 |
| RR 右后关节 | 3 | 2 | 0x001 | 0x001 |
| LW 左轮 | 4 | 1 | 0x200 | 0x201 |
| RW 右轮 | 5 | 2 | 0x200 | 0x202 |

台架可覆盖所选通道的总线、命令 ID、反馈 ID；三个值不再混用。表中达妙收发 ID 相同只是沿用工程配置，不是协议规定。接实物时必须读取调试助手中的 CAN ID / Master ID。

MIT 帧保持驱动 Kp=Kd=0，测试 PD 已在 MCU 计算成最终力矩，不重复叠加。3508 以目标反馈 ID 确定 0x200 帧中的槽位，支持电调 ID 1..4。

### 4.4 构建与 VS Code

- `build/default`、`build/bench` 分开，避免正式版复用测试版镜像。
- `.build-config` 跟踪工具链和编译参数；修改目标、总线、ID、角度、优化选项等会重编。
- Windows 目录创建和清理由 `tools/build_helper.ps1` 执行，避免 MSYS 修改 PowerShell 内联 `::` 表达式。
- 清理脚本在删除前检查绝对路径必须位于本工程 `build` 内。
- `.vscode/tasks.json` 提供台架构建、正式构建、主机测试、清理和两套烧录任务。
- 台架构建会询问电机通道、总线、发送 ID、反馈 ID、相对角度。
- `.vscode/launch.json` 分别指向两套 ELF，F5 不再共用旧路径。
- 默认开启调试符号；FreeRTOS 堆扩为 24 KiB，为台架任务栈、EKF 动态矩阵和诊断保留余量。实际栈水位仍须板上测量。

### 4.5 DM-MC02 绿色指示与三声蜂鸣

用户已确认板型为达妙 DM-MC02，不只是通用 H723 芯片。

新增 `boards/board_indicator.c/.h`：

- WS2812 使用 PA7 / SPI6，HSE 24 MHz 四分频为 6 MHz，发送低亮度绿色 GRB 数据。
- 蜂鸣器使用 PB15 / TIM12_CH2 的 4 kHz PWM。
- PB1 / TIM3_CH4 继续服务 IMU 加热，不复用。
- 绿色在启动阶段写入；三声启动音由低优先级 `send_task` 推进，每声 100 ms，间隔 150 ms，不阻塞电机任务。
- 正式版和台架版都执行，取消原来放在测试文件里的空实现。

接线依据为厂家 DM-MC02 的 SPI6 和 TIM12 示例，同时与本地同板型参考工程核对。代码已参与交叉编译；尚未在实物上确认颜色、声音和波形。绿色只表示启动指示已写入，不表示电机健康或允许运动。

### 4.6 可观察性

`bench_test_status` 可用于调试器查看：选择的电机、总线、收发 ID、相对位置、参考位置/速度、测试请求力矩、底座状态和测试故障。

UART7 遥测升级为 version 2，新增活动掩码、台架电机索引、相对实际位置、参考位置、目标角度、速度、请求力矩、测试故障和固件模式。旧版上位机需要按新结构解包。

`applied_torque_nm` 仍是软件限幅后的发送请求，不代表 CAN 已被电机确认，也不是测得的真实力矩。真实反馈力矩单独保留。

### C. 再进入 RL 适配

参考 XYEGA 工程的模型动作并非六个原生电机力矩。它先生成关节位置与轮速目标，再经 PD、雅可比及气弹簧补偿形成物理力矩。后续需要：

1. 建立训练自由度与当前六个物理通道的显式映射。
2. 标定正方向、编码零点、减速比和输出轴单位。
3. 明确训练模型使用的位置、速度和动作缩放，恢复其必要运动学与补偿。
4. 增加独占控制器选择，台架与 RL 不能同时提交命令。
5. 在保持底座保护链的前提下，再做模型推理及分阶段实机验证。

## 7. 现在可以使用的命令

在 `chassis_ref_new` 根目录运行：

```powershell
make -j32 TEST_MOTOR=1 BENCH_MOTOR=LF
make test
```

指定关节实际接线，例如 CAN2、命令 ID 5、Master ID 0x15、反向 5°：

```powershell
make -j32 TEST_MOTOR=1 BENCH_MOTOR=LF BENCH_CAN_BUS=2 BENCH_CAN_ID=0x005 BENCH_RX_ID=0x015 BENCH_TARGET_DEG=-5
```

这里 `LF` 表示使用六维数组的第 0 通道承载这次关节测试，不表示代码能够判断该电机在车上的机械安装位置。

恢复默认正式底座：

```powershell
make -j32 TEST_MOTOR=0
```
