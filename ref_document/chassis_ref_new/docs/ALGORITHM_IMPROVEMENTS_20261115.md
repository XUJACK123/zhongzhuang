## 起身接口的当前限制

没有训练完成的起身权重，本轮只提供可插入31维actor的接口。近站立姿态可直接进入BALANCE；其他姿态未注册起身actor会产生fault=5。不能把平衡actor注册为起身actor后宣称完成起身训练。

ready当前使用倾角≤8°、前向速度≤0.08 m/s、每轴角速度≤0.5 rad/s、四腿相对默认角误差≤0.15 rad及里程计置信度≥0.5。它是机载信号代理，没有接触传感器、外部辅助力或净空真值，因此仅用于控制交接，不能单独证明自主起身成功。现有40°附近倾角与物理范围保护仍贯穿全流程，尚不支持任意翻倒恢复。

独立Python起身协议与固件接口需在下一阶段对拍：Python含真实接触/净空/辅助力判据，固件使用上述代理；固件允许近站立直接接入，Python课程还包含失能静置/虚拟支撑。不能把两者称作逐帧完全一致。起身actor导出、硬件代理在仿真中的复现、两actor板上耗时仍需后续完成。

## 验证结果

- `make test`：14630个权重逐位一致；273组actor输入对拍，最大绝对误差约9.64e-5；100组观测对拍，最大误差约8.75e-8。参考网络使用标量数学，未运行PyTorch。
- 新回归覆盖9000 RPM/5 ms跨半圈轮解缠及歧义锁定、双轮不一致降级与恢复、异常四元数、IMU加速度降权与静态偏置条件、参考限幅、目标/物理范围分离、起身缺模型/超时/交接/失稳、遥测覆盖/冻结/撕裂/截断拒绝及C/Python布局。
- 假HAL回归同时覆盖输出关闭/开启配置、遥控丢失、CAN失败、反馈丢失、过倾角、调度超时；新增主循环缺起身actor时不发非零帧，以及替身actor从GETUP经过HANDOFF到BALANCE。替身测试不模拟真实机构。
- `python tools/verify_build.py --fresh`：完整ARM重编译，零warning；权重共58520字节位于FLASH，启动向量检查通过；遥测ARM符号尺寸与Python解码器匹配。最终构建资源与逐文件哈希见[验证快照](validation/algorithm_20261115.json)。

原始可重建测试输出在 [build/host/test_report.json](../build/host/test_report.json)、[build/rl/build_report.json](../build/rl/build_report.json)和[编译日志](../build/rl/build.log)。这些是离线验证结果，不是OpenOCD或现场日志。

## 参数与后续验证边界

里程计0.30 m/s残差尺度、0.25可信门槛、100 ms预测、轮解缠100 rad/s²界、IMU权重尺度均为当前工程初值。两轮同向打滑可能无法由轮约束发现；异步反馈虽降权并保留年龄，目前没有插值到共同采样时刻。IMU真实边沿时间也不代表加速度计与陀螺完全同步。用T0/T5/T6/T7数据调整并重新评估。

候选权重来自已评估部署包，但本轮改变了参考管理、IMU和里程计闭环，**旧203/203、500/500只证明当时配置，不是新固件闭环的验收**。下一步把该观测/执行链路带入仿真，做C轨迹对拍、平衡回归及起身可行性，再训练。当前MuJoCo适配源码尚未对齐这些新动态算法。

本轮没有根据0.79240历史上报比例擅自提高电流或加入未经测量的弹簧补偿；独立力矩/摩擦/弹簧辨识按T3/T4执行。CAN组控就绪不等于正向FC应答确认，软件提交不等于电机实际出力。

环形窗口只有32帧，连续记录通道尚待确定物理端口并实现；完整起身和毫秒延迟辨识不能依赖当前慢速调试器读取。当前单actor镜像的资源检查也不能代替将来新增起身权重后的FLASH/RAM、双actor最坏耗时与实物验证。
