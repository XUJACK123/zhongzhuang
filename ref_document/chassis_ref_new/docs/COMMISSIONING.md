# 从零输出联调到轮腿标定

当前已烧录零输出RL固件，六路反馈与遥控器持续接收，IMU已完成静止偏置校准和三轴符号初步核对。电机方向和绝对参考位、IMU 整圈 yaw 比例已于 2026-11-14 标定完成（`MOTOR_CALIBRATED=1`、`IMU_FRAME_VERIFIED=1`，输出仍关闭）；里程计地面真值与原训练时序仍未完成。最新实测、标定过程及原始文件见 [实机联调记录](BOARD_BRINGUP_20261113.md) 与 [改动记录](COMMISSIONING_LOG_20261113.md)。

## 1. 先把正确程序运行起来

用 VS Code **直接打开 chassis_ref_new 目录**，或在此目录的终端执行：

```powershell
make -j4
make flash-check
make flash
make monitor
```

`flash-check` 只核对镜像、路径和放行标志，不连接板卡。`flash` 使用已实测可连接的旧版 OpenOCD、Horco CMSIS-DAP v2、100 kHz SWD，烧录后校验并复位运行。当前输出标志全0，固件只发送零电流和停机命令。

唯一固件为 `build/rl/wheel_leg_rl.elf`。VS Code 的任务统一为 `RL:*`，F5入口为 `RL: DAP flash and run`；不再指向旧台架或旧底座文件。`make monitor` 通过SWD只读抓取两次RAM，不暂停、不复位、不烧录。不要同时让VS Code调试会话和命令行OpenOCD争用同一个DAP。

先看监控结果：六个节点的 `received` 持续增加，`chassis.tick` 增长，`nonzero_torque_frames=0`、`enable_commands=0`，遥控器 `valid_frames` 增长。若向量表不匹配，监控工具会拒绝解码，说明板上还不是当前RL版本。

## 2. 标定方向：先人工确认正向，再看编码器增减

固定、支撑车身，保持输出关闭。手动小幅移动机构，不让车身重量或气弹簧自行带动腿。每次记录移动前后 `encoder_counts`；这些是原始编码器计数，不是已经标定的关节角。

六项数组必须按以下顺序填写：

|数组索引|电机|反馈 ID|
|---|---|---|
|0|右髋 DM4|0x304|
|1|右小腿 DM3|0x303|
|2|右轮 M3508 ID3|0x203|
|3|左髋 DM1|0x301|
|4|左小腿 DM2|0x302|
|5|左轮 M3508 ID2|0x202|

这里的机体系为X前、Y左、Z上。腿的**规范输出臂正向**定义为：

- 髋臂：大腿从车身前方水平线朝下转的方向为正。左右腿按相同的几何定义观察，不能直接套用两侧外观的顺/逆时针。
- 小腿驱动臂：保持大腿朝向基本不变，让膝内夹角增大、腿变直，对应规范小腿驱动臂正向。这个定义来自当前归档的负alpha装配分支；不要越过机构限位或过中位。
- 轮：按车辆向前滚动的方向转动为正。

已知是上述正向小幅移动后，编码器增大记 `+1`，减小记 `-1`。跨8191/0时用：

```text
delta = ((after - before + 4096) % 8192) - 4096
sign  = +1 if delta > 0 else -1
```

如果delta为0，不能据此确定方向。两次读数之间不要转过编码器半圈。M3508反馈在转子侧，15.88减速比下轮子转约11.3度就对应转子半圈；单次轮轴人工移动约2..5度，或用连续采样展开计数。腿电机反馈已在输出轴，不再除以9。

记录得到的六个sign，填入 `ROBOT_ENCODER_SIGNS`。同一sign同时用于反馈和力矩输出，不要独立随意翻转发送端。

## 3. 标定绝对参考位：测一个实际可重复的姿态

参考姿态可以自行选择，不要求硬摆到训练默认姿态。需要测量：

1. 右大腿角 `aR`：从机身X前方水平线朝下转为正。
2. 右膝内夹角 `gR`：膝到髋与膝到轮轴两条线的夹角，完全伸直为180度。
3. 左大腿角 `aL`，按相同几何定义。
4. 左膝内夹角 `gL`。

使用角度尺、机械标记或已确认的CAD姿态。不能只根据外观估计角度。还要记录此姿态六个原始编码器计数，且轮轴保持固定。当前机构分支对应的广义关节角为：

```text
q_right_hip  = aR                  q_left_hip  = -aL
q_right_knee = gR - 270 degrees    q_left_knee = 270 degrees - gL
```

下面仅示范命令格式，数字必须换成实测值；示例姿态也不是要求机构实际摆到的位置：

```powershell
python tools/calibration_values.py `
  --counts 100 200 300 400 500 600 `
  --signs 1 -1 1 -1 1 -1 `
  --measured-leg-angles 150 100 150 100
```

工具输出三组宏，替换 `user/robot_config.h` 中的 `ROBOT_ENCODER_SIGNS`、`ROBOT_ENCODER_REFERENCE_RAD`、`ROBOT_ARM_REFERENCE_RAD`。不写电机零位，不连接硬件，不自动修改放行标志。

之后重新构建、烧录，保持输出关闭。人工小幅摆动，再摆回标记姿态：反馈应连续、方向正确、回到同一角度，左右膝范围应符合机械模型。用另一组已测姿态复核，而不是只在一个零点验证。完成后才将 `ROBOT_MOTOR_CALIBRATED` 置1；`ROBOT_ENABLE_OUTPUT` 继续为0。单圈编码器无法自动恢复断电期间任意多圈转动，重启时必须保证参考位附近的分支可唯一确定。

## 4. 核对IMU坐标

保持电机零输出，把车身固定、静止约2秒。监控中 `imu.initialized`、`imu.calibrated` 应为true，样本计数增长。检查 `omega_body_rad_s`、`accel_body_m_s2`、`gravity_body`：

|人工动作|预期符号或趋势|
|---|---|
|车身水平静止|gravity约(0,0,-1)，accel约(0,0,+9.81)，omega接近0|
|抬起车头|gravity.x变负|
|抬起左侧、降低右侧|gravity.y变负|
|从上方看车头向左转|omega.z为正，yaw增加|

这些符号按X前/Y左/Z上推导。先小幅、逐轴做动作，避免把转动中的动态加速度当成静态重力。

不一致时调整 `ROBOT_IMU_ROTATION`，将陀螺仪和加速度计一起旋转到机体系；不能只反转某个观测量掩盖错误。矩阵应是实际安装旋转，满足正交且行列式+1。然后重新静止校准、重复动作，并检查静止温漂。通过后才设 `ROBOT_IMU_FRAME_VERIFIED=1`。

## 5. 里程计与观测时序

保持 `ENABLE_OUTPUT=0`。在腿标定有效、IMU正确、反馈无异常的前提下，`make monitor` 会显示关节角、关节速度、根部XY和机体系速度。手动将车在地面向前推一段已量距离（例如1米），检查X增加、量级一致、Y没有明显横向漂移；再原地左转，检查yaw正向及非预期平移。明显误差先检查轮方向、15.88齿比、轮径0.11米、大腿/膝坐标及打滑。

该里程计假设接地且无滑移：悬空转轮也会被解释成移动，不能用悬空转轮证明地面里程计正确。确认接地工况下的误差和漂移后，才设置 `ODOMETRY_VERIFIED=1`。

`make test` 已核对31维观测的数学拼接、默认角、缩放、上一帧动作和参考轨迹公式。板上还需要量测IMU约1ms、差分速度5ms、力矩2ms、策略10ms的真实周期，检查 `inference_us`、`overruns`。`max_loop_us` 只覆盖部分控制段，完整周期需要DWT或示波器另测。

原训练提交对应的 `legged_robot.py` 尚未完整恢复，精确的观测/参考推进先后、速度差分和reset时序仍缺原环境轨迹对拍。需要恢复原版本或提供原策略的黄金输入输出及逐步轨迹，再与此部署实现比较。因此 **`POLICY_CONTRACT_VERIFIED` 目前不能因为主机测试通过就直接置1**。如果电机状态字段异常或 `inhibit` 的电机位仍置位，也需先按电机协议核查，不能绕过它启动策略。

## 6. 最后才进行受限输出验证和解锁

在放开全车RL前，需要单电机、低力矩、有超时停止的独立验证，再验证受支撑状态下的整机输出方向。当前RL入口没有单电机标定运动模式，不要用直接开启整车RL替代这一步。现有腿12Nm/轮2Nm只是部署上限，不应直接作为首次单电机标定的试验力矩。

完成并记录上述实际验证后，再设置 `ROBOT_ENABLE_OUTPUT=1`。当前控制接口已简化为：**S1 下档 = 零电流停机，其余位置 = 运行**
（上电、遥控丢失或故障后需再经过一次下档）；S2 不参与判断，没有居中/档位驻留要求。松开摇杆仍保持平衡控制。

**现在你只需要做的第一步：烧录零输出版本，确认 tick 和六路计数持续增长；然后准备四个实测机械角、六个参考计数，以及逐个手动正向移动时的前后计数。** 我可以根据这些数据计算标定宏并复核，机械姿态本身需要现场测量。
