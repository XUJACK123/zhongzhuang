# DM8009 组控诊断与一次 +10° 试验（2026-11-10）

本次已确认组控电流命令能得到电流反馈，但未实现 10° 机械运动。当前电机连着负载/机构（用户本次确认）。不能把未运动直接归因于摩擦、堵转或供电。

## 现场证据

- 初次连接 STM32H723/ST-Link，Flash 与原 build/dm8009_step.bin 完全一致。CPU 停在 HAL_Delay 的残留 FPB 断点，连续 RAM 快照 uwTick=294019 不变；清除断点并恢复后 tick 和 CAN 计数持续增长。
- 当前电机查询 ID=2，MST_ID=0，CTRL_MODE=1，PMAX=12.5，VMAX=45，TMAX=54；同时持续上传 std_id=0x302，内容符合 HKU 组控反馈。只读 MIT 查询成功不能说明 MIT 控制被执行。
- 参考 HKU_Balancing_2026/Robot/BSP/fdcan/bsp_fdcan.c 的 CAN_DAMIAO_Multi_CMD，0x3FE 使用四个 little-endian int16 电流槽。ID2 使用 bytes2..3，其余槽位归零。
- 换算参考 Robot/Modules/chassis/balance/motor.hpp 与 Robot/Modules/motor/motor_dm.c：Kt=1.261575 Nm/A，41.044776 A/16384。组控位置为8192 count/圈，速度为0.01 rpm/count；闭环不再使用MIT速度的低速量化值。

## 代码改动

- 默认 DM_USE_MULTI=1，保留 MIT 查询/读参及原 MIT 可选发送路径。
- 新增组控位置、速度、实测电流、计数及时间戳；闭环采用组控角度/速度。组控反馈丢失或状态异常立即停止，即使 MIT 查询仍有回复。
- 所有 FD 停止路径先发送全零 0x3FE。不能依赖 FD 是否将反馈 state 改为0。
- 默认保持 +10°、目标2°/s、0.50 Nm、0.10 Nm/s缓升、12秒截止、12°位移及10°/s超速保护。
- 单独准备 DIRECT_TEST=1 LOAD_TEST=1 候选：1.50 Nm、0.20 Nm/s、20秒；仍是相同10°目标/2°每秒/12°边界，必须显式写入一次启动请求。用户随后确认至少12°安全行程并授权一次，已完成下面的加载测试。默认遥控版不采用这些较高参数。

## 操作与验证

自动审批曾拒绝直接重连读取最终快照，担心 MCU 被暂停影响停止；随后采用 init（不halt、不reset、不接GDB）、先写 abort 请求、等待MCU执行、再dump的方法，成功确认停止。一次 resume 命令返回 target not halted，也表明当时 CPU 仍在运行。没有因这次拒绝而再次触发动作。

通过 tools/test.ps1：MIT路径、自动/固定ID、只读扫描、组控发送/槽位/符号/限幅、FD被忽略时零电流停止、组控断联、8192编码器回绕，以及直接单次测试。默认与加载候选均通过对应离线测试与 ARM 交叉编译。离线测试不证明实际机构能移动。

当前结论：组控电流链路有反馈响应，但在已授权范围内仍未完成10°。需确认机构自由度、支撑/卸载条件或实际相电流/驱动响应后再决定下一步，不能直接判定负载太大或机械堵转。

## 随后继续的实机结果与当前状态

用户确认此前关闭过电机电源，重新上电后bus-off消失、READY恢复。随后一次启动被预检查拒绝（result6、未输出运动电流），原因未在旧镜像中编码记录；对静止反馈可见约2°/s速度噪声，因此专用测试的组控预启动速度门槛改为3°/s，并新增precheck_flags记录，不更改运行中10°/s保护。
